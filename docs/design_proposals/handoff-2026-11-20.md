## 1. Goal

One place to manage every LLM API backend, exposing a unified API layer to coding agents and to the owner's
self-built personal knowledge-management (PKM) app. The PKM app is still being designed; the gateway is its
model-access layer only (notes, indexing and retrieval belong in the app).

## 3. Conventions other agents should keep

- **One recording point**: every call ends in `recordSuccess` / `recordError` (`server/callerpolicy.go`), which feed metrics, per-key stats and the usage ledger. Attempts put served model, key fingerprint, route, TTFT and stream errors on the request's `callInfo` (`server/callinfo.go`) via `noteAttempt`. New endpoints must call `withCall(...)` and end through these two functions.
- **Commit point**: nothing reaches a streaming client before an attempt has produced content (`streamReader.hold`). Errors after that are in-stream errors in the client's protocol (`clientStream.writeStreamError` / `encodeInStreamError`); never fabricate a finish.
- **Failover-only codes** (`router.IsStreamQualityError`): `upstream_incomplete`, `empty_reply`, `upstream_finish_error`, `first_token_timeout`, `upstream_idle_timeout`, `upstream_key_limit` — fail over without key penalties or provider cooldown.
- **Vendor rules are scoped to the vendor** (preset/ID or model name), applied as JSON patches in `buildUpstreamPayload`, so passthrough gets them too.
- **Masking fails closed**; transforms run after masking (operator text is never masked); `unredacted` providers get the plain body and are kept out of `ResponseStore`.
- **Config precedence**: persisted runtime overrides > env > `providers.yaml` > preset. `DELETE /api/gateway/providers/{id}/overrides` resets on restart.
- **Tests**: mock upstreams with `rtFunc` transports and `io.Pipe` bodies (`server/stream_test.go`), in-memory SQLite named after the test. Note: `go test -count>1` fails `TestRouterPrecedenceCooldownAndPolicy` because shared-cache in-memory DBs keep state across reruns; use `-count=1`.
- Commit style: small imperative English commits with the Claude co-author trailer; release by pushing `main` and an annotated `vX.Y.Z` tag.

## 5. Deployment notes (generic)

- Docker image pins a tag (`:1.1.0`); the release workflow's `latest` tag is only enabled on the default
  branch, so **tag pushes do not move `latest`** — deployments must pin the version.
- Secrets go in a `.env` loaded with `env_file:` (a compose-directory `.env` alone only feeds `${VAR}`
  interpolation). Non-secret settings stay in `environment:`.
- Reaching the console by hostname needs `NEXUS_ADMIN_HOSTS`. A host Ollama needs
  `NEXUS_OLLAMA_BASE_URL=http://host.docker.internal:11434`, `extra_hosts: host.docker.internal:host-gateway`,
  and `host.docker.internal` in `NO_PROXY` when an HTTP(S) proxy is set.
- Back up `nexus.db` **and** `nexus.redact.key` together (placeholders and prompt caches depend on the key).
- Ollama `:cloud` models run on Ollama's servers; with masking on keep `unredacted: false` for `ollama`.

## 6. Findings to act on

### 6.1 Native Responses API is wider than our presets assume (probed 2026-11-20) — **done** (`f05e9ff`)

Implemented as planned; see `api-aggregation-gateway.md` § *Native Responses Passthrough*. Later probes added:
AMD keeps turns (`previous_response_id` worked) but is still treated as stateless (expansion is always safe);
DeepSeek-reasoner no longer requires reasoning items on tool turns (magpie's 2026-10-12 `reasonFirst` rule did not
reproduce), and all four accept foreign item ids, so neither patch was ported. Ollama's response ids are short
(`resp_409853`); the store keys by id only, so cross-provider collisions are possible but unlikely.

Only `openai` declares an `openai_responses` endpoint, so Responses clients reach every other backend through
IR translation (which works, and bridges `previous_response_id` with the gateway's `ResponseStore`).
A direct probe of `POST <base>/v1/responses` found:

| Backend | Native `/responses` | Stateful `previous_response_id` |
| --- | --- | --- |
| openai | yes | yes |
| ollama | yes (stream events complete) | not verified (assume no) |
| openrouter | yes | not verified |
| deepseek | yes | **no** — accepted but context silently lost |
| amd | yes | not verified |
| nvidia, gemini (OpenAI-compat) | no (404) | — |

Why the presets look Anthropic-heavy: vendors added Anthropic-compatible endpoints early for Claude Code;
Responses support arrived later and the presets predate it. **Trap**: simply adding `openai_responses` to these
presets would switch Responses clients to passthrough, and DeepSeek would drop multi-turn context. Plan:
add a quirk (e.g. `stateless_responses`) under which passthrough expands `previous_response_id` from
`ResponseStore` into `input` (and strips the field), verify statefulness per vendor, then enable native
Responses for ollama, openrouter, deepseek, amd with tests.

### 6.2 Embeddings default: OpenAI, not Voyage

The Voyage AI preset (embeddings + rerank only, `no_chat`) came in with v1.0.0 (`906cfb1`) because magpie ships
it and it gave `/v1/rerank` a built-in backend. The owner prefers mainstream providers: the PKM app should use
OpenAI `text-embedding-3-small` (or `-large`) behind a pinned alias such as `pkm-embed` (DB model route,
policy `pinned`). Pending decision: drop `voyage` from `DefaultPresetOrder` / `config/providers.yaml` (keep the
generic `no_chat` + rerank support for custom providers) — `/v1/rerank` then has no built-in backend until one
is configured (Cohere/Jina/Voyage via YAML).

### 6.3 Known gaps

- Live Claude prompt-cache hits are unverified (no direct Anthropic key on the dev host); unit-tested only.
- `fastest` uses provider EWMA latency, not TTFT; credit-error cooldown ladder is not persisted across restarts.
- `/v1/models` lists chat models only (embedding/rerank models are not advertised).
- Ledger is in SQLite next to request logs; very large DBs (GBs of request logs) slow backups.
